# 标定与"保真度裁判"

预览器最大的风险不是崩，而是**悄悄画歪**：某个单位换算错了，画面看着像但和剪映不一样。
所以需要一个不依赖人眼的对照物（oracle）。

## 现成的 oracle：`draft_cover.jpg`

封面是**剪映自己渲染出来的像素**（626/645 个草稿都有，且与画布等比）。
`preview.py calibrate <draft>` 会在时间线上均匀取 N 帧，用本预览器渲染，再和封面比相似度：

```bash
python <S>/preview.py calibrate "<草稿>" --samples 8
```

实测（<草稿>，缩到 360×640 逐像素 MSE→相似度）：

```
best: t=18.052s  similarity=0.7116  layers=1  media_missing=0
spread: [0.5411, 0.5455, 0.7116, 0.7116, 0.6346, 0.6364, 0.5411, 0.6987]
```

解读规则：
- **最高分应显著高于均值**，且 >0.85 才认为几何模型（fit 模式 + transform + 旋转）与剪映一致。
- 上面这组 0.71 属于"形状对、细节偏"。已知混淆因素：封面可能取自**另一条时间线**（该草稿现有
  `时间线01` 与 `包裹staging` 两条）、封面是 JPEG 而截图是 PNG、未做色彩管理、
  以及封面取自"无字幕"帧而我们的采样点未必对上。
- 因此它现在用于**回归**（改动前后同一套命令，分数掉了就是画坏了），
  还不能当作绝对保真度证明。

## 文字尺寸：已用真实导出标定（2026-09-28）

`em_px = font_size × 画布宽 × 0.00625`，即 **`width/160`**；1080 宽时 `字号 10 → 67.5px`。

标定方法（`python -m jypreview.tools.measure_export --video <导出mp4> --draft <草稿>`）：
- 参考片 `<导出视频路径>/<export>.mp4`（1080x1920@30，剪映导出）
- 取两行已知字幕：`一旦你用上个半年`(8 字) 墨迹宽 540px、`精度差距直接拉开了`(9 字) 610px
  → 逐字推进 **67.5 / 67.8 px**，两行一致；
- 墨迹高 60–63px，与该字体（`HelloFont_ID_JianSong_95.ttf`）实测 `ink/em = 0.90` 自洽；
- 草稿里字幕众数字号 = 10（79/82 条）→ `px/字号单位 = 6.75`。

交叉验证：横屏草稿字幕默认 size 6 → `1920×0.00625×6 = 72px`，竖屏 size 10 → 67.5px，
绝对字号一致；而旧的 `width/100` 给出 108 vs 72（差 1.5 倍），正是"字幕偏大"的来源。

**唯一残留假设**：那两行字幕用的是草稿众数字号 10（导出对应的文本已被后续编辑改掉，无法逐条配对）。
若日后拿到"文本未改动"的导出，重跑 `measure_export` 即可复核；`--text-scale` / `--text-basis` 仍可覆盖。

## 已知的其它未定标量

| 量 | 当前取值 | 状态 |
|---|---|---|
| `line_spacing` | 行高 = `em × (1 + line_spacing)`，默认 `0.02` | 未标定 |
| `letter_spacing` | `letter_spacing × em`（pyJianYingDraft 记 `UI×0.05`） | 未标定 |
| 描边宽度 | `strokes[].width × em`（不乘 2） | 目测合理，未标定 |
| 阴影位移 | `distance/100 × em`，角度→dx/dy | 目测合理（曾按整 em 算导致字幕下方出现巨大重影） |
| `fit_mode` | `contain_unrotated` | 由 -90° 横屏口播填满 9:16 反推，`--fit-mode contain_rotated` 可切 |
| 转场时长 | 不改时间线长度，窗口居中于切点 | 由 222 处相邻片段 `gap=0` 实测得出 |

## 回归基线

`~/.jypreview/calibrate/` 与 `shots/` 下的 PNG 是 sha256 稳定的（同一 t 两次截图 sha 相同，已验证），
适合当基线：改渲染代码后重跑同一批 `shot` 命令，比对 sha 或做图像 diff。
